Challenges

• Missing langchain_openai dependency: The dashboard_api container crashed on startup after importing the sql_insights pipeline because langchain_openai was not installed in that service's environment, requiring a proxy architecture redesign.
• asyncpg Pool vs Connection mismatch: The sql_insights pipeline calls pool.acquire() internally, so passing a bare asyncpg.connect() connection caused a runtime AttributeError that only appeared after the LLM had already generated a query.
• Missing Depends import in main.py: Adding the monitor/run endpoint with Depends(get_db) caused a NameError on startup because Depends was never imported into main.py — the existing endpoints used a different injection pattern via a shared state object.
• SQL schema drift: The SEMANTIC_SCHEMA prompt used by the NL2SQL agent referenced columns (e.g. product_name on supply_chain_records) that no longer existed after the schema was normalized with a separate products table, causing generated queries to fail silently.
• Next.js API route gaps: Several new backend endpoints (e.g. /inventory/all, /monitor/run) required corresponding Next.js proxy route files to be created manually — missing routes caused silent 404s that were not obvious from the frontend error messages.

Solutions

• Proxy architecture: Instead of installing langchain in dashboard_api, refactored analytics.py to use httpx to proxy requests to the internal langgraph_agent service, which already had all LangChain dependencies installed — keeping services decoupled and images lean.
• asyncpg.create_pool() for single requests: Replaced the bare asyncpg.connect() call with asyncpg.create_pool(min_size=1, max_size=2) inside the langgraph_agent endpoint handler and closed the pool in a finally block, satisfying the pipeline's pool.acquire() contract without modifying the pipeline code.
• app.state.db pattern: Instead of adding the missing Depends import and wiring up a dependency injector just for one endpoint, accessed the database pool directly from app.state.db which is set during lifespan startup — a simpler and consistent approach used by other internal endpoints.
• Schema prompt update: Added a PRODUCTS table entry to the SEMANTIC_SCHEMA with join relationship definitions, and added a RULES section instructing the LLM to always join via product_id and include product_name in SELECT statements, fixing the column-not-found errors.
• Systematic Next.js route creation: Established a pattern of always creating the app/api/dashboard/[route]/route.ts proxy file alongside each new backend endpoint, ensuring the full request chain (browser → Next.js → FastAPI → Postgres) is complete before testing.
