Challenges

• Duplicate Proposal Backlogs: The 60-second background scheduler was overly eager. When it detected an inventory breach, it triggered the agent, which then correctly paused in a Human-In-The-Loop (HITL) state waiting for admin approval. However, 60 seconds later, the scheduler detected the same breach and triggered a duplicate workflow, creating a rapidly growing backlog of identical proposals.
• Hardcoded Magic Numbers: The background agents were initially built with hardcoded scheduling intervals and configuration variables spread across multiple scripts, which made adjustments difficult and increased the risk of deployment errors.
• Inconsistent Background Output: Some background scripts used standard print statements while others used proper logging, making it difficult to trace events systematically in the console when multiple agents were running simultaneously.

Solutions

• Pending State DB Check: Added a pending status lock check in PostgreSQL before invoking the LangGraph pipelines. The scheduler now skips triggering new workflows if a pending task for that SKU already exists, effectively solving the duplicate backlog issue.
• Centralized Configuration: Abstracted all environment configurations and intervals out of the Python scripts into a single config.yaml file to ensure clean, maintainable code architecture.
• Standardized Logging: Refactored daily_digest.py to use Python's built-in logging module, ensuring all background agents output consistent, timestamped logs with appropriate severity levels.
